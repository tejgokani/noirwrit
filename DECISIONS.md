# Decisions

Each entry: date, decision, reason.

## 2026-10-28

- **Phase 0 answers** are in `config/requirements.json`: local web app, dark and light themes, reader mode with a chapter sidebar, a progress/ETA bar, keyboard shortcuts, public MIT repo, own model plus a tiny pretrained embedder, public domain data only, English, 3000-word chapters with a noir-first genre mix.
- **GPU and budget.** The answers first conflicted: RunPod (paid) as the provider with a $0 budget. The user resolved it as Kaggle free first, with RunPod/Vast.ai as a fallback capped at $8. All cost guards use $8.
- **Package layout.** plan.md lists `tokenizer/ model/ train/ runtime/ memory/ planner/ app/` at the top level. Those names make poor top-level Python packages (`model`, `app` and `memory` collide easily) and would block a clean PyPI install. They live under `noirwrit/` instead: `noirwrit/tokenizer`, `noirwrit/model`, and so on. `data/ tools/ tests/ config/ docs/` stay at the top level. Large outputs go to the gitignored `artifacts/` folder.
- **Python.** The system default is 3.14. The venv uses Python 3.11 through `uv` for wheel availability (torch, WeasyPrint).
- **Disk.** Only 34 GB free (93% used). Keep the raw corpus compressed or deleted after cleaning, keep only the latest and best checkpoints, and never download multi-GB datasets.
- **Thermal check without sudo.** `powermetrics` needs root and passwordless sudo is not set up. The guard tries `sudo -n powermetrics` and falls back to `pmset -g therm` (CPU speed limit and warning level), which works without a password.
- **Guard polling.** RSS is polled every 0.5 s even though the plan says 30 s, because memory can spike past the ceiling between 30 s checks. Swap and thermal checks run every 30 s.
- **No AI attribution** on commits, per the user's standing preference.
- **Strict public domain rule.** A title is kept only if every contributor died by 1930, its first publication year is well established as 1930 or earlier (`KNOWN_YEARS`), a pulp issue date in the title is 1930 or earlier, or its own front matter carries a copyright or publication year of 1930 or earlier. A front matter year after 1930 drops the book even if another rule passed. This drops many likely-PD books (for example Burroughs and Barrie), which is the intended "unsure means out" trade.
- **Noir set.** Gutenberg has *The Maltese Falcon* (1930) and *Little Caesar* (1929) but not *Red Harvest* or *The Dain Curse*. The noir voice set is widened with American pulp crime from 1930 or earlier: Packard's underworld novels, *Nick Carter Stories* weeklies (dated in the title), and dated Raoul Whitfield stories. It is small by nature and gets a short, low-LR finishing stage.
- **Validation split.** The last 2% of every book goes to val, instead of hashing whole books into val. With a few hundred books, whole-book hashing gave one val book for general and none for noir.
- **MPS memory.** Metal allocations do not appear in RSS on Apple Silicon. The guard's first tiny probe pushed the Mac into a 1.1 GB swap storm while reporting 0.46 GB RSS (the guard still caught it through the swap check). The guard now enforces the ceiling on max(RSS, physical footprint), read through `proc_pid_rusage`. Local runs use micro-batch 8 with gradient accumulation 4; micro-batch 32 needs about 1 GB just for the logits.
- **Prompting a base model.** A 100M base model cannot follow instructions or control tokens it never saw. The planner writes a short prose lead-in for each beat and the model continues it, with retrieved memory, the previous summary and a bible slice in front as plain prose. The special tokens stay reserved in the vocabulary for an optional later fine-tune.
- **Vector index.** Exact cosine search over a float32 matrix in memory, loaded from SQLite. A story library holds thousands to low hundreds of thousands of chunks; brute force is a few milliseconds there and needs no FAISS or sqlite-vec native build.
- **Embedder fallback.** MiniLM (all-MiniLM-L6-v2) is the embedder when installed and cached. A deterministic hashing embedder (word unigrams and bigrams, 384 dims) is the fallback and the test embedder, so the app runs fully offline even before the MiniLM download.
- **WeasyPrint on macOS.** WeasyPrint opens GLib and Pango by bare name, which dyld does not find in /opt/homebrew/lib, and preloading by absolute path does not help. The PDF exporter imports WeasyPrint in-process when possible and otherwise renders in a subprocess with `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib`.
- **GGUF export without the converter script.** Homebrew llama.cpp ships the binaries but not `convert_hf_to_gguf.py`. Noirwrit writes the GGUF directly with the `gguf` package (from the llama.cpp project), applying the same q/k RoPE permutation the official converter uses, then uses `llama-quantize`.
- **Live typing.** The worker publishes each scene's cleaned text about ten times a second (`live` table); the server streams it over Server-Sent Events; the reader types the difference at a reading pace (Slow 22, Natural 45, Fast 110 characters a second, or Instant) with pauses at punctuation, and rewinds to the common prefix when a name fix changes text behind the cursor. llama.cpp output is read unbuffered so tokens arrive as they are printed. Typing applies while a chapter is being written by default; finished chapters show at once (configurable).
- **Best-of-N reranking is opt-in.** On the tiny model, best-of-3 per 140-token chunk (scored by the model's own log-probability plus dictionary, repetition and quote checks) moved the non-word rate from 1.8% to 1.5%, raised repeated trigrams slightly, and was 8 times slower. It is kept as the Quality setting for the trained base model; Fast and Balanced stream every token. Sampling defaults moved to temperature 0.75, top-p 0.9, min-p 0.05, top-k 60, repeat penalty 1.12 over the last 256 tokens.
- **Prose quality comes from training, not post-processing.** The tiny model (5M parameters, 3.5M tokens, 7 minutes) exists to prove the pipeline and cannot write grammatical English. The base model trained online is the fix; no pretrained language model is used, per the dependency policy.

## 2026-10-29

- **Code travels inside the Kaggle kernel.** Kaggle reported a new dataset version ready within seconds, but the kernel mounted the old one, so a fix never ran. The launcher now embeds the code (a 0.36 MB base64 tar.gz) in the kernel script; the dataset only carries the shards.
- **Memory on the T4.** Micro-batch 16 at a 2048 context ran out of memory for both base and small. The probe now halves the micro-batch and doubles gradient accumulation on out-of-memory, keeping 65,536 tokens per step (the run used 8 x 4).
- **Released weights are fp16.** `final-weights.pt` holds the best noir-stage checkpoint without optimizer state (210 MB instead of about 1.2 GB), since this Mac's connection is slow. Full checkpoints stay on Kaggle for resume.
- **Name check.** "Noirwrit" is free on PyPI, npm, GitHub and Hugging Face. One similar project, NoirWriter (GitHub, Dharun1704), is logged in `docs/NAME_CHECK.md`. Not renamed; the user decides. The USPTO search could not be scripted and is listed as a manual step.
- **PyPI deferred.** The user chose to release v0.1.0 on GitHub and Hugging Face without a PyPI package for now. Install is from a clone (`make setup`).
